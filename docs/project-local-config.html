1. 使能 / 禁用当前项目的格式化

1

项目内永久设置

当前配置使用 vim.b.conform_enable 决定某个 buffer 保存时是否执行 Conform。

为整个项目启用

任何有 filetype 的项目文件都会在保存时格式化。

vim.api.nvim_create_autocmd('FileType', {
  pattern = '*',
  callback = function(event)
    vim.b[event.buf].conform_enable = true
  end,
  desc = 'Enable formatting for this project',
})
为整个项目禁用

即使其他全局自动命令打开格式化，项目规则也会明确关闭。

vim.api.nvim_create_autocmd('FileType', {
  pattern = '*',
  callback = function(event)
    vim.b[event.buf].conform_enable = false
  end,
  desc = 'Disable formatting for this project',
})

只使能指定文件类型

vim.api.nvim_create_autocmd('FileType', {
  pattern = { 'c', 'cpp' },
  callback = function(event)
    vim.b[event.buf].conform_enable = true
  end,
  desc = 'Enable project formatting for C/C++',
})
临时命令影响范围
:FormatEnable打开当前 buffer 的保存格式化。
:FormatDisable关闭当前 buffer 的保存格式化。
:FormatDisable!设置全局总开关为关闭，当前 Neovim 会话都不格式化。
:FormatEnable!重新打开全局总开关；各 buffer 仍以自己的开关为准。

2. 覆盖当前项目 ft 的制表符参数

2

用 FileType 设置 buffer-local 选项

不要直接改全局缩进；按文件类型写入 vim.bo[event.buf]，不会影响帮助页或终端。

参数含义
expandtabtrue 用空格代替 Tab；false 保留真实 Tab。
tabstop一个真实 Tab 在屏幕上显示多少列。
shiftwidth>>、<< 和自动缩进一次移动多少列。
softtabstop插入模式按 Tab / Backspace 时一次操作多少列；设为 0 表示不做软 Tab 模拟。
C / C++：4 空格 
vim.api.nvim_create_autocmd('FileType', {
  pattern = { 'c', 'cpp' },
  callback = function(event)
    local bo = vim.bo[event.buf]
    bo.expandtab = true
    bo.tabstop = 4
    bo.shiftwidth = 4
    bo.softtabstop = 4
  end,
})
Go / Make：真实 Tab，宽 4 
vim.api.nvim_create_autocmd('FileType', {
  pattern = { 'go', 'make' },
  callback = function(event)
    local bo = vim.bo[event.buf]
    bo.expandtab = false
    bo.tabstop = 4
    bo.shiftwidth = 4
    bo.softtabstop = 0
  end,
})

多个 ft 使用一张配置表

local indent = {
  c =    { expandtab = true,  width = 4 },
  cpp =  { expandtab = true,  width = 4 },
  lua =  { expandtab = true,  width = 2 },
  go =   { expandtab = false, width = 4 },
  make = { expandtab = false, width = 4 },
}

vim.api.nvim_create_autocmd('FileType', {
  pattern = vim.tbl_keys(indent),
  callback = function(event)
    local rule = indent[event.match]
    local bo = vim.bo[event.buf]
    bo.expandtab = rule.expandtab
    bo.tabstop = rule.width
    bo.shiftwidth = rule.width
    bo.softtabstop = rule.expandtab and rule.width or 0
  end,
  desc = 'Apply project indentation',
})

3. 覆盖当前项目的 :make

3

核心是 makeprg 与 errorformat

:make 执行 makeprg，输出按 errorformat 解析后进入 quickfix。

CMake 项目 
vim.opt.makeprg = 'cmake --build build --parallel 10'

vim.keymap.set('n', '<leader>pm', '<cmd>make<CR>', {
  desc = 'Make project',
})
普通 Makefile 项目 
vim.opt.makeprg = 'make -j10'

vim.keymap.set('n', '<leader>pm', '<cmd>make<CR>', {
  desc = 'Make project',
})
vim.keymap.set('n', '<leader>pc', '<cmd>copen<CR>', {
  desc = 'Open build errors',
})
传递目标：:make clean、:make install 会把参数追加到 makeprg 后面。构建失败后用 :copen 查看列表，:cnext / :cprev 跳转错误。

如果编译器输出没有被正确识别

优先使用 Neovim 内置 compiler 配置，它会同时设置 makeprg 和 errorformat：

-- 常见值包括 gcc、clang、go、pytest 等；以 :compiler 列表为准
vim.cmd 'compiler gcc'
vim.opt.makeprg = 'cmake --build build --parallel 10'

4. 新增项目快捷键 / 命令

4

命令承载动作，快捷键只负责调用

复杂动作先定义成 :Project... 命令，再绑定按键，更容易在命令行单独调试。

最简单的快捷键 
vim.keymap.set('n', '<leader>pb', '<cmd>CMakeBuild<CR>', {
  desc = 'Build project',
  silent = true,
})
Lua 回调快捷键 
vim.keymap.set('n', '<leader>pr', function()
  vim.cmd 'CMakeRun'
  vim.notify 'Started project target'
end, {
  desc = 'Run project',
})

新增项目命令，再绑定快捷键

vim.api.nvim_create_user_command('ProjectBuild', function()
  vim.cmd 'make'
end, {
  desc = 'Build current project',
})

vim.api.nvim_create_user_command('ProjectTest', function()
  vim.cmd 'botright new'
  vim.fn.termopen {
    'ctest', '--test-dir', 'build', '--output-on-failure',
  }
  vim.cmd 'startinsert'
end, {
  desc = 'Test current project',
})

vim.keymap.set('n', '<leader>pb', '<cmd>ProjectBuild<CR>', {
  desc = 'Build project',
})
vim.keymap.set('n', '<leader>pt', '<cmd>ProjectTest<CR>', {
  desc = 'Test project',
})

只在某种 ft 中出现的快捷键

vim.api.nvim_create_autocmd('FileType', {
  pattern = { 'c', 'cpp' },
  callback = function(event)
    vim.keymap.set('n', '<leader>ph', '<cmd>LspClangdSwitchSourceHeader<CR>', {
      buffer = event.buf,
      desc = 'Switch source/header',
    })
  end,
})
建议：项目快捷键统一使用一个前缀，例如 <leader>p...，并始终填写 desc，这样 which-key 和 Telescope keymaps 中更容易识别。

完整模板：四件事放在一起

-- .nvim.lua

-- 1. 当前项目：只格式化 C / C++
vim.api.nvim_create_autocmd('FileType', {
  pattern = { 'c', 'cpp' },
  callback = function(event)
    vim.b[event.buf].conform_enable = true
  end,
})

-- 2. 当前项目：覆盖不同 ft 的缩进
local indent = {
  c =    { expandtab = true,  width = 4 },
  cpp =  { expandtab = true,  width = 4 },
  cmake = { expandtab = true, width = 2 },
  make = { expandtab = false, width = 4 },
}

vim.api.nvim_create_autocmd('FileType', {
  pattern = vim.tbl_keys(indent),
  callback = function(event)
    local rule = indent[event.match]
    local bo = vim.bo[event.buf]
    bo.expandtab = rule.expandtab
    bo.tabstop = rule.width
    bo.shiftwidth = rule.width
    bo.softtabstop = rule.expandtab and rule.width or 0
  end,
})

-- 3. 当前项目：覆盖 :make
vim.cmd 'compiler gcc'
vim.opt.makeprg = 'cmake --build build --parallel 10'

-- 4. 当前项目：命令与快捷键
vim.api.nvim_create_user_command('ProjectBuild', function()
  vim.cmd 'make'
end, { desc = 'Build current project' })

vim.keymap.set('n', '<leader>pb', '<cmd>ProjectBuild<CR>', {
  desc = 'Build project',
})
vim.keymap.set('n', '<leader>pe', '<cmd>copen<CR>', {
  desc = 'Open build errors',
})

最后检查

  • 修改 `.nvim.lua` 后重新执行 :trust。
  • 用 :setlocal expandtab? tabstop? shiftwidth? softtabstop? 检查当前 buffer。
  • 用 :set makeprg? 和 :set errorformat? 检查 make 配置。
  • 用 :map <leader>p 检查项目快捷键，用 :command Project 检查项目命令。
  • 格式化异常时先检查 :FormatEnable，再运行 :ConformInfo。
本页采用柔和浅色主题，可离线打开；示例对应当前配置中的 Conform、cmake-tools.nvim 和原生 :make。
